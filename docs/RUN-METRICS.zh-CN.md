# 运行日志与跨电脑统计口径

适用版本：2026.10.28.4；日志统计口径版本：metric_schema_version=2。

在程序中导出日志 ZIP 后，使用 runs.csv 做汇总，使用 runs.jsonl 保留完整数值。
记录不包含聊天正文、回答、附件、会话数据库、API 密钥或本机完整路径。
导出前仍会按允许字段过滤；速度的原始数值不再提前四舍五入，界面负责显示小数位。

| 指标 | 定义与比较限制 |
| --- | --- |
| first_token_seconds | 工作区开始处理本次请求到首段非空回答文本的时间，包含上下文准备、模型准备和输入处理。计时终点为应用收到首段可见文本，与模型内部首 token 和桌面绘制耗时分别统计。 |
| tokens_per_second | 后端报告的生成速率。tokens_per_second_source=native_backend 表示原生后端计时；worker_generated_ids 表示 worker 按生成 ID 计数。不同后端的原生分母和首 token 约定可能不同。 |
| observed_decode_tokens_per_second | 首个正原生累计计数到最后一次计数增长的 token 增量除以应用观测时间。首批全部 token 排除，重复最终计数不延长区间。用于比较流式交付速度，包含应用和传输开销，不是纯计算内核速度。 |
| observed_decode_tokens / observed_decode_seconds | 上述观测速率的分子与分母，便于复算。只有一次有效计数、计数倒退或缺失时不生成观测速率，不能用 SSE 消息数量代替 token 数。 |
| request_seconds | 工作区本次处理至流结束、报错或取消被观察到的耗时。随后工作区发起的清理不计入；模型运行器内部完成后才返回的工作仍计入。 |
| whole_request_tokens_per_second | 已知生成 token 总数除以上述请求耗时，包含准备及首字等待。不能与纯生成速率混用。 |
| model_ready_seconds | 后端启动到健康检查通过的时间。分层读取可能在健康检查后继续读取权重，不能将其单独当作完整加载时间。 |

先按模型 SHA256、量化、运行模式、文本/视觉模式、软件版本、统计口径版本、
CPU、内存、上下文、线程和 batch/ubatch 参数分组，再比较冷启动与热启动、
首字时长、生成速率和整轮耗时。模型 SHA256 来自模型清单，不表示每轮重新校验权重。
历史日志没有新口径版本时保持空值，不补造精度，也不与新版观测速率直接合并。
从 2026.10.28.3 开始，Windows 的 CPU 型号优先读取本机硬件注册表中的
ProcessorNameString，例如 i5-1235U，避免把不同 CPU 只记成相同的 Family/Model 通用标识。
读取不可用时仍回退到系统提供的处理器/架构名称；不采集序列号、设备唯一标识或用户名。
历史记录保留原有 CPU 名称，导出时不会用当前电脑型号回填其他电脑的旧数据。
错误和取消记录单独统计；缺失速度保留为空值。短请求与持续输出按样本长度分别汇总。

性能优化目标：27B 4 token/s、70B 0.5 token/s。当前短测见 `docs/VALIDATION.md`。
