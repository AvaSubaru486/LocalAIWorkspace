# 低配置电脑上的大参数模型运行

## 标题牌｜900 × 220 mm

Local AI Workspace：低配置电脑上的大参数模型运行

## 左侧｜300 × 1200 mm

### 摘要

Local AI Workspace 将 8B、27B、70B 模型与运行环境整合为本地 AI 工作区。通过低比特量化、按需读取和进程管理，在普通电脑上探索大参数模型的运行路径。

**16 GiB**

参考机内存 · i5-1235U · Intel 核显

### 研究背景

**大模型与有限内存**

70B 量化权重约 14.77 GiB。系统、应用、上下文缓存和计算缓冲还需要空间，权重驻留必须合理安排。

**部署与测量的门槛**

自行部署需要组合模型、后端、依赖和参数；不同工具的日志格式也给多机对比带来额外工作。

### 设计思路

**让环境完整**

模型、界面和运行库一起准备。

**让资源有序**

按需读取，管理切换与回收。

**让结果可比较**

统一记录首字、速度与内存。

## 中间｜600 × 1200 mm

### 核心原理：把读取与计算安排在有限内存中

模型完整保存在 SSD。内存接收当前计算需要的权重，CPU 按层推进计算，再生成下一个 token。减少同时驻留的权重，会增加读取与等待。

**SSD：保存完整 70B 权重**

本版 IQ1_S 文件约 15.85 GB

**按需读取**

取用当前层权重

**内存驻留**

安排有限缓冲

**CPU 计算**

执行当前层运算

推进后续层 → 结合上下文 → 生成下一个 token

70B 配置上限：4 GiB 驻留 / 12 GiB 进程提交

### 技术实现

**低比特量化**

较少比特记录权重，
平衡存储与数值精度。

**两类读取路径**

8B / 27B 使用内存映射，
70B 使用分层 CPU 读取。

**完整生命周期**

预算、启动、切换、取消，
以及任务结束后的回收。

### 自主实现与创新点

**统一桌面操作**

聊天、历史、附件与 Python 工作区

**模型配置与调度**

固定模型身份，连接文字与视觉路径

**进程资源管理**

预算、取消、模型切换与子进程回收

**跨设备性能日志**

统一字段，导出 ZIP / CSV / JSONL

基础模型：Qwen / Gemma / Llama；量化与引擎采用 Unsloth、llama.cpp 等上游组件。

## 右侧｜300 × 1200 mm

### 运行实测

参考机：i5-1235U、16 GiB RAM、Intel 核显；三档模型均完成离线短回答。

| 模型 | 解码 token/s | 首字 / 秒 |
| --- | ---: | ---: |
| 8B | 6.134 | 3.47 |
| 27B | 0.295 | 17.38 |
| 70B | 0.123 | 52.28 |

短输出样本：8B / 27B / 70B 分别生成 3 / 4 / 3 个 token。
