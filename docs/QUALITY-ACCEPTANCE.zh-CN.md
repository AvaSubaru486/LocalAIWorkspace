# 三模型质量与速度验收（2026-10-28）

本版本的交付范围是 Qwen3 8B、Gemma 3 27B 和 Llama 3.3 70B 三款文字模型。用户设定的速度目标为：27B 至少 4 token/s，70B 至少 0.5 token/s。用户允许在本机慢一些，因此速度目标作为发布前的测量目标，不把一次短回答写成保证。

## 验收原则

每轮测试记录模型身份、量化、权重 SHA256、后端 SHA256、线程、上下文、批大小、GPU 层数、模型加载时间、首字时间、生成 token 数、decode token/s、整轮 token/s、RSS、提交内存、系统可用内存、结束原因和子进程回收结果。测试只运行一个重任务，不关闭用户程序、不放宽内存保护、不把 SSE chunk 数量当作 token 数。

比较常规自部署与本项目时，必须固定模型文件及哈希、推理引擎版本、提示内容、上下文、线程、GPU 卸载、输出 token 数和电脑负载。ZIP 大小、窗口启动时间、单个短回答或模型“能启动”都不能代替持续 decode 测量。

## 参考设备

当前设备为 Intel Core i5-1235U、10 核/12 线程、16 GiB RAM、Intel UHD 核显，无可用 NVIDIA CUDA。默认进程提交上限为 12 GiB；8B/27B 的驻留预算按用户设置与当时可用内存计算，70B 分层路径另有最多 4 GiB 驻留上限。进程超过自身运行上限时，测试应记录原因。

## 运行日志

桌面端“导出运行日志 ZIP”提供不含聊天内容的统计。导出包包含设备、软件版本、模型哈希、量化、运行参数、首字时长、模型就绪时间、生成 token 数、token/s、内存和错误类型；过滤掉提示词、回答、附件、会话数据库、个人配置、密钥和本机绝对路径。多台电脑的数据应按模型哈希、量化和运行模式分组。

## 质量结论

参数规模、量化文件大小、启动成功和 token/s 都不能自动换算成“智商”或能力保留百分比。若要报告质量保持比例，需要同一模型高精度版本、合法参考数据、预先确定的多任务评分规则和重复测量；没有这些数据时，结论应写为“能力未验证”。单道题通过也只能说明该题通过，不能证明整体能力比例。
