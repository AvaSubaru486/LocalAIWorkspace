# 模型内存管理

模型进程使用两类资源上限：私有提交量和驻留工作集。启动前，根据当时可用内存与用户设置计算预算；预算不足时提示原因。运行期间检查模型进程及其子进程的内存占用，超出自身上限时结束任务并记录状态。

- 8B / 27B：使用内存映射，按启动时的可用预算安排驻留。
- 70B：使用分层 CPU 读取，驻留上限为 4 GiB。
- 默认模型进程提交上限：12 GiB。
- 三档模型的最低可用模型预算：2 GiB。

上述数值是配置上限；运行日志记录实际驻留、私有提交、首字时长、生成速度和结束原因。减少同时驻留的权重会增加读取与等待，模型文件、上下文和后台负载共同影响运行表现。

切换、取消和退出会回收应用启动的模型子进程。日志统计包采用字段白名单，包含运行指标与环境信息。
